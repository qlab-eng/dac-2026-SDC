On-Device Clinical Speech Agent Contest at DAC 2026(current)

Contest

1. Introduction

Speech is one of the earliest and most accessible biomarkers for cognitive and developmental disorders. In older adults, changes in speech fluency, lexical diversity, and syntactic complexity are well-documented indicators of Alzheimer's Disease and Related Dementias (ADRD). In children, delayed or atypical language patterns can signal developmental language disorders (DLD) that benefit from early intervention.

Today, clinical speech-language assessments are predominantly conducted in specialized facilities by trained professionals, limiting accessibility for underserved populations. Cloud-based AI speech analysis tools exist, but they require uploading sensitive clinical audio recordings to remote servers, raising serious privacy and regulatory concerns (e.g., HIPAA, GDPR). This is especially problematic for vulnerable populations such as elderly patients and children.

Edge deployment offers a compelling alternative: by processing speech entirely on-device, sensitive audio never leaves the local environment. This aligns naturally with IoT healthcare scenarios such as smart home monitoring systems for aging-in-place, wearable clinical assistants, and tablet-based screening tools in pediatric clinics. However, building such a pipeline on resource-constrained devices is technically challenging, as it requires integrating automatic speech recognition (ASR), linguistic feature extraction, and language model-based reasoning under tight compute, memory, and latency budgets.

2. Objective

The goal of this contest is to design and implement an end-to-end on-device clinical speech agent that takes a raw speech recording as input and produces a clinical screening prediction as output, all running on a given edge platform.

The contest consists of two tracks. Participants may enter one or both tracks:

  • Track 1: ADRD Speech Screening. Given a speech recording from a picture description task (e.g., the Cookie Theft picture), the agent must classify the speaker as either cognitively healthy (HC) or exhibiting signs of cognitive impairment (CI). The agent should process the audio on-device, transcribe it, extract relevant linguistic and acoustic features, and output a binary classification with a confidence score.

  • Track 2: Child Developmental Language Assessment. Given a speech recording from a child during a narrative or conversational task, the agent must assess the child's language development level. The agent should transcribe the speech, compute age-appropriate linguistic metrics (e.g., MLU, lexical diversity, grammatical complexity), and output a developmental classification (typical vs. at-risk).

For both tracks, the entire pipeline — from raw audio input to clinical prediction output — must execute on the given edge device. No cloud API calls are permitted during inference.

3. Pipeline Architecture

The expected pipeline consists of three stages, though participants are free to design alternative architectures as long as all processing remains on-device:

  • Stage 1: On-Device ASR. Transcribe the input speech recording into text. Participants may use any ASR model (e.g., Whisper variants, wav2letter, or custom models) optimized for edge deployment. Handling of disfluencies, pauses, and speech errors is particularly important for clinical populations.

  • Stage 2: Linguistic Feature Extraction. Extract clinically relevant features from the transcript and/or audio signal. Examples include: speech rate, pause frequency and duration, type-token ratio, mean length of utterance (MLU), syntactic complexity, phonemic errors, and acoustic features (e.g., jitter, shimmer, formant patterns).

  • Stage 3: Clinical Classification. Use a small language model (SLM) or a lightweight classifier to produce the final clinical prediction. Participants may use fine-tuned SLMs, traditional ML classifiers, or hybrid approaches. The classifier must output a binary label and a confidence score.

4. Data

Track 1 (ADRD): We will provide a curated dataset based on publicly available clinical speech corpora, including recordings from the ADReSS/ADReSSo challenge datasets (derived from DementiaBank's Pitt Corpus). Each sample consists of a speech recording from a picture description task with associated clinical labels (HC vs. CI) and demographic metadata. Details on the exact dataset split and preprocessing will be released upon registration.

Track 2 (Child Language): We will provide a curated dataset drawn from publicly available child language corpora (e.g., subsets of CHILDES). Each sample consists of a recorded speech segment with associated developmental language assessments. Details will be released upon registration.

Participants may use additional public datasets for training, but must disclose all data sources in their submission. Use of private or proprietary clinical data is not permitted to ensure reproducibility.

5. Platform

All submissions will be evaluated on an NVIDIA Jetson Orin Nano (8 GB unified memory, 40 TOPS INT8), representing a realistic edge deployment target for IoT healthcare devices. The device will run Ubuntu 22.04 with JetPack SDK.

Participants should ensure their solutions are compatible with this environment. We will provide a Docker container specification for reproducible evaluation. Only Python-based solutions will be accepted.

6. Scoring

The final score is a weighted combination of clinical accuracy and practical deployment metrics. It is defined as follows:

Clinical Accuracy (50%):

  • Classification Performance: We report the macro F1 score of the clinical classification on a held-out test set. This accounts for class imbalance in clinical datasets. The F1 score ranges from 0 to 1.

    $$ F1_{norm} = \frac{F1 - F1_{min}}{F1_{max} - F1_{min}} $$ where \( F1_{min} = 0.4 \) (random baseline level) and \( F1_{max} = 0.95 \). If \( F1 < 0.4 \), the score is set to 0. If \( F1 > 0.95 \), the score is set to 1.

  • Transcript Quality (Track 1 only): Word Error Rate (WER) of the ASR output compared to reference transcripts. Lower is better.

    $$ WER_{norm} = 1 - \frac{WER - WER_{min}}{WER_{max} - WER_{min}} $$ where \( WER_{min} = 0.05 \) and \( WER_{max} = 0.60 \).

Deployment Efficiency (50%):

  • End-to-End Latency: Average inference time per sample (audio in → prediction out), measured over 20 runs on the Jetson Orin Nano. The latency score is:

    $$ L = 1 - \frac{Lat - L_{min}}{L_{max} - L_{min}} $$ where \( L_{min} = 2s \) and \( L_{max} = 60s \). If latency is below 2s, \( L = 1 \). If above 60s, \( L = 0 \).

  • Peak Memory Usage: Maximum resident memory during inference. The memory score is:

    $$ M = 1 - \frac{Mem - M_{min}}{M_{max} - M_{min}} $$ where \( M_{min} = 0.5 \text{ GB} \) and \( M_{max} = 7.5 \text{ GB} \). If below 0.5 GB, \( M = 1 \). If above 7.5 GB, \( M = 0 \).

Final Score:

For Track 1: $$ Score = \left( 0.25 \times F1_{norm} + 0.25 \times WER_{norm} + 0.30 \times L + 0.20 \times M \right) \times 100 $$

For Track 2: $$ Score = \left( 0.50 \times F1_{norm} + 0.30 \times L + 0.20 \times M \right) \times 100 $$

7. Demo

A baseline implementation will be provided. The baseline pipeline uses a quantized Whisper-tiny model for ASR, rule-based linguistic feature extraction, and a lightweight classifier for clinical prediction. Details and source code will be released upon the dataset release date.
