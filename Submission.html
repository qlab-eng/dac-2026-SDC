Submission

Submission Requirements

Each submission must include the following components:

1. Docker Container

Your complete pipeline must be packaged as a Docker container compatible with the NVIDIA Jetson Orin Nano (ARM64, JetPack SDK). The container should accept a raw audio file (WAV, 16kHz mono) as input and produce a JSON output containing:

  • prediction: the classification label (e.g., "HC" / "CI" for Track 1; "typical" / "at-risk" for Track 2)
  • confidence: a float between 0 and 1
  • transcript: the ASR-generated transcript (Track 1 only, used for WER evaluation)

We will provide a template Dockerfile and an example inference script. Your container must run without network access.

2. Source Code

All source code must be included in the submission and must be open-source (MIT, Apache 2.0, or BSD license). The code should be well-documented with a README that includes:

  • Environment setup instructions
  • Training procedure (if applicable)
  • Inference instructions
  • List of all dependencies and their versions
  • List of all datasets used for training

3. Technical Report

A technical report of up to 4 pages (excluding references) in IEEE conference format describing:

  • Pipeline architecture and design choices
  • Model selection and optimization techniques (e.g., quantization, pruning, distillation)
  • Training methodology and data augmentation strategies
  • Ablation studies or design justifications
  • Self-reported results on the provided validation set
Submission Format

Please package your submission as a single .tar.gz archive with the following structure: 

team_name_trackN.tar.gz
├── docker/
│   ├── Dockerfile
│   └── ... (all files needed to build the container)
├── src/
│   ├── inference.py
│   ├── ... (source code)
│   └── README.md
├── models/
│   └── ... (pre-trained model weights)
└── report/
    └── technical_report.pdf
Submission Portal

Important Notes
  • Only Python-based solutions are accepted (C/C++ extensions via ONNX Runtime or TensorRT are allowed).
  • The Docker container must build and run on ARM64 / JetPack without modification by the organizers.
  • Each team may submit up to 3 times before the final deadline. Only the last submission will be evaluated.
  • Late submissions will not be accepted.
  • Finalists will be required to make their code publicly available on GitHub.
